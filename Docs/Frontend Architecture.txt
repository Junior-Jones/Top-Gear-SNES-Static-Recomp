Top Gear Windows Frontend Architecture
Version 28 / Launcher 1.0.0

Rendering
The static core owns a deterministic 256x224 BGRA frame. The Windows frontend
copies completed frames into a two-buffer presentation object. SDL3 selects a
Direct3D renderer on Windows and falls back to its software renderer if a GPU
renderer cannot be created. VSync and 4:3 correction are user settings. Native
Win32 menus, buttons and dialogs remain separate from the custom-drawn game
surface.

F8 screenshot capture keeps the Windows chrome but replaces the game rectangle
with one newly decoded static-core frame. This avoids black and partially stale
fullscreen captures returned by PrintWindow.

Audio
The static S-SMP/S-DSP core and WAV recorder retain exact 32,040 Hz stereo PCM.
The frontend queues that native stream to SDL3, which uses the selected Windows
device and resamples to its output format. Queue depth is kept around the user's
latency target with a bounded plus/minus 0.25 percent frequency correction.
This correction affects speaker presentation only, never core state or WAV
recording. Queue failures, underruns, depth, target and output sample rate are
available in About diagnostics.

Input
Keyboard gameplay bindings are stored as physical scan-code tokens, with old
virtual-key INI entries migrated when loaded. Controller state is updated once
per host frame and then read for both players. Each player remembers a preferred
SDL GUID across launches. Analogue controls use a configurable deadzone and
hysteresis. Keyboard, gamepad, or combined input can be selected per player.
Impossible opposing directions are removed unless explicitly allowed.

Timing and diagnostics
The high-resolution waitable timer remains the primary NTSC clock. A short host
stall advances up to eight emulated frames, renders only the last frame and
preserves real-time audio. Longer stalls are resynchronized and counted. A
600-frame input-history ring records the exact masks supplied to the core for
debugging and deterministic reproduction. About reports presentation, audio,
timer and history counters.

Portability
SDL and the Visual C++ runtime are statically linked in Release builds. No SDL
DLL or VC redistributable is required. Windows system components such as
Kernel32, User32, GDI32, COMCTL32, OLE32, DXGI and Direct3D are provided by
Windows 10 and 11.
