# Explore - Insert audio

## Phase goal

Add accessible audio cues to Top Gear's otherwise silent menus by reusing the game's own Full Static S-SMP/S-DSP sound effects.  The first milestone is intentionally narrow: the opening OPTIONS screen must play one skid cue whenever Up or Down actually changes the highlighted row.

## Test 1 Part 1 - opening OPTIONS menu

The rendered menu after pressing Start has five rows, not two:

1. `1 PLAYER`
2. `SKILL LEVEL`
3. `COUNTRY`
4. `SPEED KPH`
5. `PLAY GAME`

WRAM `$005A` is the proved row selector (`0-4`).  The generated input routine at `$0F:91DD-$0F:91FC` handles Up/Down, wraps at the ends, and commits the accepted new row with `STA $5A` at `$0F:91FC`.  That commit is the prototype cue hook.  Sound is not tied directly to a raw controller bit, so an input that does not change the selection cannot create a false cue.

## Why Player-2 skid command $15 is used

Player-1 skid `$0A` uses DSP voice 5.  A live main-menu DSP capture proves the Title song is already using voice 5 (`SRCN $05`, active envelope), so `$0A` would steal a live music channel.  Player-2 skid `$15` is the mirrored form of the same skid effect on DSP voice 7.  At the tested menu point voice 7 is inactive, making `$15` the least disruptive in-game skid command for navigation cues.

## Why the skid BRR must be relocated

The Title upload bank has no SRCN `$10` directory entry: ARAM `$8A40-$8A43` is zero.  The race bank normally installs skid SRCN `$10` at `$B580`, but Title source 7 occupies `$B000-$BC8C`; copying the race skid to its original address would corrupt the Title song.

The accessibility mod therefore copies the exact ROM-owned skid resource block from ROM file `$03DB39-$03E138` (the same bytes that race setup installs at ARAM `$B580-$BB7F`) into unused Title ARAM `$C000-$C5FF`.  It then installs SRCN `$10` as start/loop `$C000/$C000` at directory entry `$8A40`.

This relocation is proved non-overlapping for the Title state used by the menu: the final Title BRR source ends at `$BF7A`; DSP echo uses ESA `$39`, EDL `$01`, therefore `$3900-$40FF`; `$C000-$C5FF` is outside both.

## One-shot APUIO1 protocol

APUIO1 is level-sensitive.  Holding a nonzero sound command causes repeated dispatches, which was the earlier SFX-recorder mistake.  The menu mod uses an asynchronous state machine synchronized with the running core:

1. write skid command `$15` at the current APU rendezvous;
2. wait until the S-SMP echoes `$15` as acknowledgement;
3. immediately write neutral `$00`;
4. wait for neutral acknowledgement;
5. return idle.

This differs from the offline recorder's blocking pulse helper: it never advances audio ahead of the running S-CPU, so there is no backwards-master-clock failure on the following game frame.

## Prototype proof

`static-recomp/tests/test_menu_insert_audio.c` boots normally, holds Start to reach the menu, performs four Down movements followed by four Up movements, and requires:

- selector sequence reaches row 4 and returns to row 0;
- exactly 8 accepted navigation changes;
- exactly 8 skid command starts, acknowledgements, clears and neutral acknowledgements;
- no queued command left behind;
- relocated ARAM bytes exactly equal the ROM skid resource;
- original Title `$B580-$BB7F` remains unchanged;
- zero S-SMP AOT failures;
- zero static S-DSP failures.

When passed an optional WAV pathname the same executable records the real mixed game audio, including Title music and the inserted menu cues, at 32,040 Hz stereo 16-bit PCM.

## Implementation lesson from prototype bring-up

The first temporary hook was added only to the normal generated `$0F:91FC`
translation unit and therefore never fired in the actual tested route, even
though `$005A` changed correctly.  The running route was executing through the
v22 reentry shard.  The production prototype consequently hooks both the normal
and reentry forms of the same proved static instruction.  This is important for
future menu hooks: locate the semantic instruction in both current production
dispatch paths before treating a silent hook as evidence that the WRAM mapping
is wrong.

A second failed research approach attempted to use the blocking public sound
command helper while the S-CPU was already running.  That helper intentionally
advances the APU for offline recording and caused the next normal game sync to
report that the APU master clock had moved backwards.  Runtime menu cues must
therefore use the asynchronous acknowledge-and-clear state machine integrated
with the existing audio rendezvous; the blocking recorder helper is not a
runtime injection API.

# Test 1 Part 2 - import the SimCity menu-navigation cue

## Objective

Part 1 proved that Top Gear's menu selector can issue an accessibility cue at the exact accepted highlight commit.  Part 2 replaces the temporary Top Gear skid cue with the menu-navigation sound from the SNES version of SimCity while preserving Top Gear's own Full Static audio engine and Title music.

The transfer deliberately does **not** import SimCity's S-SMP driver.  It imports only the proven sound asset and the minimum DSP playback contract needed to reproduce that one cue.

## SimCity Linux qualification

The supplied `SimCity-SNES-Static-Recomp-1.4.0-Source.zip` was rebuilt as a native Linux static-core/headless application.  The exact USA ROM used for research has SHA-256:

`e9c0bc05511e05a0d7c3e7cc42e761e1e8e532d46f59b9854b6902e1a2e9dd0a`

The required smoke test ran naturally for 20 seconds.  A screenshot at approximately 10 seconds showed the normal SimCity title screen.  The Full Static audio path remained known with zero static-audio route failures.

The required navigation test then waited 10 seconds, pressed Start, observed the menu, and performed Down, Down, Up, Up.  The menu contains:

1. `PRACTICE`
2. `START NEW CITY`
3. `SELECT SCENARIO`

The live selector is WRAM/direct-page `$003E`.  The accepted sequence was `1 -> 2 -> 3 -> 2 -> 1`.

## S-CPU command path for the SimCity cue

The accepted navigation path commits the new menu row at S-CPU `$03:D35A` and then selects sound command `$06`:

- `$03:E578`: `LDA #$06`
- `$03:E57A`: `STA $05`
- NMI/audio service `$00:9890`: reads direct-page `$05`
- `$00:9892`: writes that value to APUIO2 / `$2142`
- `$00:9895`: clears direct-page `$05`

Thus `$06` is the proved SimCity menu-navigation command; it is not identified by waveform guessing.

## Exact SimCity DSP/BRR resource

A live DSP trace of one accepted Down movement proved that command `$06` temporarily owns DSP voice 7 with:

- DSP DIR `$35` -> source directory `$3500`
- SRCN `$03`
- source-directory entry `$350C`
- BRR start `$3AD1`
- BRR loop `$3AEC`
- 6 BRR blocks / 54 bytes
- left/right volume `$3C/$3C`
- pitch `$17BB`
- ADSR1 `$FE`
- ADSR2 `$F5`
- GAIN `$70`
- echo disabled for voice 7 while the cue is active

The 54-byte BRR SHA-256 is:

`acc24c77261f84da0f6704959ec38981b03befa8dba4b1a43f70a30b4e34c928`

The last BRR block has END=1 and LOOP=1.  Therefore the sample cannot simply be keyed on and left running; doing so would repeat the cue.

## Exact finite lifetime

The hidden DSP-write trace proved the source game's finite event envelope rather than inventing a duration:

- pre-event voice-7 key-off: master clock `281250530`
- cue key-on: master clock `281862836`
- cue key-off: master clock `282583664`
- key-on to key-off: `720828` SNES master clocks, approximately `33.562 ms`
- original voice-7 instrument restoration begins at master clock `283015568`
- echo state is restored at master clock `283019000`

The Top Gear transplant therefore reproduces a finite key-on/key-off/release/restore sequence.  This specifically avoids repeating-audio failures learned during the earlier SFX exploration.

## Transfer boundary into Top Gear

Top Gear retains its own S-SMP/S-DSP machine, music driver and Title-song state.  Only the 54-byte SimCity BRR resource and the proved DSP playback parameters are imported.

The BRR body is installed into the previously proved free Title ARAM region at `$C000`.  SimCity's loop offset is `$001B`, so Top Gear SRCN `$10` is installed in its own source directory as:

- start `$C000`
- loop `$C01B`
- directory entry `$8A40-$8A43`

The original Title resource region `$B580-$BB7F` is not overwritten.

At an accepted Top Gear `$005A` menu-selector change, the mod:

1. snapshots Top Gear DSP voice-7 registers and EON;
2. clears any prior voice-7 KOFF state;
3. temporarily disables echo for voice 7;
4. configures voice 7 with the imported SimCity volume, pitch, SRCN and envelope;
5. keys on voice 7;
6. requests key-off after the proved `720828`-master-clock active interval;
7. clears the level-sensitive KOFF bit on the next normal audio rendezvous;
8. restores Top Gear's saved voice-7 registers and echo state after the proved release/restoration interval.

All mod DSP writes occur only after normal Full Static synchronization; the mod does not advance the APU independently of the S-CPU timeline.

## Lessons for future cross-game audio insertion

Do not transplant a whole foreign audio driver when one small effect is wanted.  First prove the source game's S-CPU command, then the exact DSP voice/SRCN/resource/envelope/pitch and finite lifetime.  Import the smallest asset boundary into the destination game's existing audio system.

Do not infer a one-shot merely because a WAV sounds short.  Check the BRR END/LOOP bits and capture the real source game's KON/KOFF timing.  The SimCity cue itself is loop-capable; its one-shot behavior comes from driver-controlled key-off.

Do not overwrite destination-game music resources or assume a DSP voice is disposable.  Use a proved free ARAM destination and save/restore the destination voice state around the cue.
